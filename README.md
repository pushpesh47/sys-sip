# Jio Fiber SIP Provisioner

A Python utility for provisioning a software SIP client as an authorized JioFiber Voice secondary device and generating the SIP configuration required for a Linux SIP client.

The project communicates with the JioFiber router on the local network and uses the router's provisioning interface to obtain the SIP/IMS configuration.

> **Important:** This project is intended for use with your own JioFiber connection and an account for which you are authorized to provision a secondary device.

## Current Status

The provisioning and SIP registration pipeline has been verified end-to-end:

- `request_account` works.
- A deterministic secondary-device identity is generated by the provisioner.
- The device `add` request works.
- Jio sends the OTP by SMS.
- `WITRCSeConfigCookie` is received and preserved for the OTP session.
- OTP verification works.
- SIP provisioning XML is returned.
- SIP username, realm, password, public/private identities, registrar and related values are extracted.
- `.env` is generated automatically.
- Device `remove` works.
- Removing and provisioning the device again causes Jio to issue a fresh OTP.
- PJSUA2 is installed and usable from the project's Python 3.14 virtual environment.
- PJSUA2 can create a TLS transport on the local SIP port.
- Jio's SIP endpoint challenges the initial REGISTER with `401 Unauthorized`.
- PJSUA2 successfully performs Digest/MD5 authentication.
- The authenticated REGISTER receives `200 OK`.
- Registration callback reports HTTP-equivalent SIP status `200 OK` and an active registration.
- RFC 5626 outbound behavior was disabled with `AccountConfig.natConfig.sipOutboundUse = False`.
- With RFC 5626 outbound disabled, PJSUA2 no longer adds the unwanted automatic `;ob` parameter or its automatically generated instance identifier.
- The REGISTER Contact can therefore use the provisioned/device-specific SIP instance parameters required by the Jio endpoint.

## JioFiber Network Endpoints

The provisioner communicates with the JioFiber router through the local provisioning endpoints:

```text
http://jiofiber.local.html:8080/request_account
https://jiofiber.local.html:8443/
```

The router's commonly used LAN address is:

```text
192.168.29.1
```

If the local hostname is not resolvable, the provisioner can use the router's LAN address.

The SIP service is provisioned separately and is exposed by the router on TLS port:

```text
5068
```

### Credential security

`.env` contains the SIP authentication password and must be treated as a secret.

Never:

- commit `.env` to Git
- publish `.env`
- paste `SIP_PASSWORD` into an issue or chat
- publish provisioning cookies
- publish OTPs
- include SIP credentials in logs

Recommended `.gitignore` entries:

```gitignore
.env
.env.bak
```

If SIP credentials are exposed, remove the authorized secondary device and provision it again so Jio issues a fresh credential set.

# SIP/TLS Registration with PJSUA2

## Registration Architecture

The verified registration path is:

```text
Linux SIP client
      │
      │ TLS :5068
      ▼
JioFiber router
      │
      ├── REGISTER
      │
      ├── 401 Unauthorized
      │
      ├── Digest/MD5 Authorization
      │
      └── 200 OK
```

The SIP authentication realm is provisioned by Jio and is normally:

```text
br.wln.ims.jio.com
```

The registrar is taken from:

```text
REGISTRAR_HOST
REGISTRAR_PORT
```

Do not hardcode account-specific credentials into source code.

## PJSUA2 RFC 5626 Configuration

PJSUA2 enables RFC 5626 outbound behavior by default.

For this JioFiber registration path, that automatic behavior must be disabled:

```python
account_config.natConfig.sipOutboundUse = False
```

Without this setting, PJSUA2 can automatically generate outbound-related Contact information including:

```text
;ob
```

and an automatically generated `+sip.instance` value.

With RFC 5626 outbound disabled, the registration test can provide the required Contact parameters explicitly:

```text
;+sip.instance="<device-instance>"
;reg-id=1
;video
```

The exact device instance must come from the provisioning/device identity used by the SIP client. Do not blindly copy an instance identifier from another installation.

---

## PJSUA2 Contact Configuration

The PJSUA2 registration test uses:

```python
account_config.regConfig.contactParams = (
    ";+sip.instance="<device-instance>""
    ";reg-id=1"
    ";video"
)
```

The Contact URI itself is generated by PJSUA2 from the TLS transport address.

The verified behavior is that the resulting REGISTER contains the intended local SIP Contact and does not contain the unwanted automatically generated RFC 5626 `;ob` parameter.

## Digest Authentication

Jio challenges the initial REGISTER with:

```text
401 Unauthorized
```

The challenge contains:

```text
algorithm=MD5
realm="br.wln.ims.jio.com"
nonce="<server-generated-value>"
```

PJSUA2 handles the Digest authentication exchange when configured with the provisioned credentials.

The authentication credential configuration is conceptually:

```python
cred = pjsua2.AuthCredInfo()
cred.scheme = "Digest"
cred.realm = realm
cred.username = username
cred.data = password
cred.dataType = 0
```

Never hardcode the password.

---

## TLS Transport

The registration test creates a PJSUA2 TLS transport:

```python
transport_config = pjsua2.TransportConfig()
transport_config.port = 5068
transport_config.tlsConfig.verifyServer = False
```

The transport is created with:

```python
endpoint.transportCreate(
    pjsua2.PJSIP_TRANSPORT_TLS,
    transport_config
)
```

### TLS verification note

The JioFiber router uses a local SIP/TLS service. The current verified test disables server certificate verification:

```python
transport_config.tlsConfig.verifyServer = False
```

This is appropriate for the current local-router reverse-engineering/test environment, but it should not be interpreted as a general recommendation for Internet-facing SIP services.

---

## Provisioning Session Handling

The provisioning `add` request and OTP verification must use the same session.

The implementation explicitly transfers the Jio:

```text
WITRCSeConfigCookie
```

from the provisioning response into the Python `requests.Session`.

The same session is then used for OTP verification.

This is required because the OTP operation is associated with the provisioning session.

## Troubleshooting

### Router provisioning endpoint is unreachable

Test the router:

```bash
curl -sS --max-time 5 http://192.168.29.1:8080/request_account
```

Test the HTTPS provisioning endpoint:

```bash
curl -k -i --max-time 10 https://192.168.29.1:8443/
```

The computer must be connected to the JioFiber LAN.

### OTP is not received

Verify that the router provisioning endpoint is reachable and that the secondary device is not already authorized.

Do not repeatedly request OTPs unnecessarily.

If the device is already authorized:

```bash
python jio_fiber_sip_provisioner.py --remove
```

Then start a new provisioning cycle.

### OTP verification fails

Ensure that:

1. The OTP belongs to the current provisioning attempt.
2. The `WITRCSeConfigCookie` from the same `add` request is retained.
3. The same HTTP session is used for verification.

If necessary, remove the device and begin a fresh provisioning cycle.

### PJSUA2 cannot be imported

Verify the active Python environment:

```bash
which python
python --version
```

Then verify:

```bash
python -c "import pjsua2; print(pjsua2.__file__)"
```

The module must be installed for the same Python interpreter that runs `test_pjsua2_register.py`.

### Registration receives `401 Unauthorized`

A first `401 Unauthorized` is expected.

PJSUA2 should then send an authenticated REGISTER.

The expected successful sequence is:

```text
401 Unauthorized
        ↓
Digest Authorization
        ↓
200 OK
```

If the authenticated REGISTER also fails, verify the generated `.env` values and ensure that the SIP credentials have not expired or been replaced by a newer provisioning cycle.

### Registration succeeds but Contact contains `;ob`

Verify that the registration test contains:

```python
account_config.natConfig.sipOutboundUse = False
```

Do not modify the underlying PJSIP source code unless a later requirement demonstrates that the configuration API cannot provide the required behavior.
